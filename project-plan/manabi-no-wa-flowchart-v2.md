## A. システム全体俯瞰フロー

**目的**: 利用開始からロール別ダッシュボード表示までの大局フロー  
**対応要件**: F-AUTH-05, システム全体  
**アクター**: 全ユーザ , SYS  

### フロー

```text

  A-01 ( サービス利用開始 )
         ↓
  A-02 [ PWA / Web アクセス ]
         ↓
  A-03 < 認証セッション有? > ─ No → (○ B-01) 認証フローBへ
         │ Yes                          ↓
         ↓ ←──── 認証フローBから戻り ──┘
  A-04 = users.role 参照 =
         ↓
  A-05 < ロール判定 (6種) >
         ├ 教師 → (○ D-01)(○ G-01)
         ├ 生徒 → (○ E-01)
         ├ V    → (○ C-01)(○ D-10)
         ├ 地域 → (○ F-01)
         ├ 管理 → (○ H-07)(○ I-01)(○ K-01)
         └ 教委 → (○ H-07)(○ K-01)
         ↓
  A-06 [ ロール別ダッシュボード表示 ]
         ↓
  A-07 ( 利用継続 / 終了 )

```

### 工程詳細

| ID | アクター | 処理内容 | I/O | 次処理 |
|---|---|---|---|---|
| A-01 | - | サービス利用開始 | - | → A-02 |
| A-02 | 全 | PWA/Webアクセス | I: /URL/ | → A-03 |
| A-03 | SYS | 認証セッション有? | I: cookie | Y→A-04 / N→B-01 |
| A-04 | SYS | users.role 参照 | I: =DB= | → A-05 |
| A-05 | SYS | ロール判定 (6種) | I: role | 各ロール → A-06 |
| A-06 | SYS | ダッシュボード表示 | O: 画面 | → A-07 |
| A-07 | - | 利用継続 / 終了 | - | - |

> **注**
> ・教委は管理と同等のロール権限。統計ダッシュボード閲覧可
> ・(○ X-NN) 表記は他フローXの工程NNへの結合子
> ・A-04 の users.role は Supabase users テーブルの列
> ・A-05 の「6種」は通常ユーザ 6 ロール(教師・生徒・V・地域・管理・教委)。
> 残り 2 ロールは本フロー A を経由しない:
> - サービス運営者は別 admin URL (B 注参照) からアクセス
> - 保護者は永続アカウントを持たず、メールリンク経由で同意のみ実施

### 処理の補足

アクセス時にまず認証セッションの有無を確認し、無ければ認証フロー(B)へ進む。認証済みなら users.role を参照して6ロールを判定し、それぞれのダッシュボードへ振り分ける。サービス運営者と保護者はこの俯瞰フローを通らず、別経路でアクセスする。
